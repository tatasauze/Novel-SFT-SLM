程式碼硬性要求：

一、先讀取並复用 SFT 代碼中的模板

1. 請嘗試從 `train_en2zh_sft.py` 中找到以下內容並复用：

3. ORPO 的 prompt 必須與 SFT 推理模板一致。

4. 如果 JSONL 中的 `prompt` 欄位只是英文原文，請自動包成：

   ```text
   ### English
   {prompt}
   ### Chinese
   ```

5. 如果 JSONL 中的 `prompt` 欄位已經包含完整模板，例如已經有 `### Chinese`，則不要重複包裝。

6. `chosen` 和 `rejected` 應該只是中文回答，不應該包含英文原文或模板前綴。
   - 如果發現 `chosen` 或 `rejected` 中包含 `### English` 或 `### Chinese`，請嘗試移除模板前綴。
   - 如果無法安全移除，請印出警告並過濾該筆資料。

二、資料前處理

1. 使用 `datasets` 或 `pandas` 讀取 JSONL。

2. 標準化欄位：
   - 將 `reject` 改名為 `rejected`。
   - 如果同時有 `reject` 和 `rejected`，優先使用 `rejected`。
   - 最終保留欄位：
     - `prompt`
     - `chosen`
     - `rejected`

3. 清洗資料：
   - 刪除缺少 `prompt`、`chosen` 或 `rejected` 的樣本。
   - 對三個字串都做 `strip()`。
   - 刪除空字串樣本。
   - 刪除 `chosen == rejected` 的樣本。
   - 可選：刪除 `chosen` 或 `rejected` 長度極短的樣本，例如小於 2 個字元。
   - 印出清洗前與清洗後資料數量。

4. 使用 tokenizer 計算長度：
   - 對每一筆資料計算：
     - `prompt` token 數
     - `chosen` token 數
     - `rejected` token 數
     - `prompt + chosen` 總 token 數
     - `prompt + rejected` 總 token 數
   - 印出：
     - min
     - p50
     - p90
     - p95
     - p99
     - max
   - 如果樣本總長度超過 `MAX_SEQ_LENGTH`，請過濾掉該樣本，並印出被過濾的數量。
   - 不要隨意截斷 `chosen` 或 `rejected` 中文輸出，尤其是不要截斷人工譯文。

5. 去重：
   - 使用 `prompt` 做去重。
   - 如果相同 `prompt` 出現多次，只保留第一筆，或保留 `chosen` 較長的一筆。
   - 印出去重前後數量。

三、資料切分

1. 資料總數約 2500 筆。

2. 建議切分比例：


3. 請固定 `seed=42`。

4. 切分時確保：
   - 同一個 `prompt` 不可以同時出現在 train / validation / test。
   - validation 和 test 不能洩漏到 train。

5. 印出：
   - 每個 split 的樣本數。
   - 每個 split 中 `chosen` 和 `rejected` 的平均 token 數。

6. 如果資料量太小，導致某個 split 為 0，請報錯並提示需要調整比例。

1. 使用 Unsloth 載入模型。

5. 如果 SFT 模型是完整模型：

五、ORPO 訓練

1. 請使用 TRL 的 `ORPOTrainer` 和 `ORPOConfig`。

2. 如果 `unsloth_orpo_template.py` 中有官方 ORPO 寫法，請優先使用其資料格式與參數。

4. 如果需要自行 tokenize，請確保：
   - prompt 部分不計算 loss。
   - `chosen` 和 `rejected` 的 response 部分才計算 loss。
   - labels 中 prompt 對應位置設為 `-100`。
   - `chosen` 和 `rejected` 結尾要有正確的 `eos_token`。
   - 不要重複加 `eos_token`。

5. ORPO 訓練參數建議：

   ```python
   OUTPUT_DIR = "./qwen3-4b-en2zh-orpo"
   NUM_TRAIN_EPOCHS = 1
   PER_DEVICE_TRAIN_BATCH_SIZE = 1
   PER_DEVICE_EVAL_BATCH_SIZE = 1
   GRADIENT_ACCUMULATION_STEPS = 16
   LEARNING_RATE = 5e-6
   WARMUP_RATIO = 0.05
   LR_SCHEDULER_TYPE = "cosine"
   OPTIM = "adamw_8bit"
   WEIGHT_DECAY = 0.01
   MAX_GRAD_NORM = 1.0
   LOGGING_STEPS = 5
   EVAL_STRATEGY = "epoch"
   SAVE_STRATEGY = "epoch"
   LOAD_BEST_MODEL_AT_END = True
   METRIC_FOR_BEST_MODEL = "eval_loss"
   GREATER_IS_BETTER = False
   SEED = 42
   REPORT_TO = "none"
   BF16 = True if supported else False
   FP16 = True if BF16 not supported else False
   ```

6. ORPO 特有參數：
   - 請檢查 `ORPOConfig` 支持哪些參數。
   - 可能出現的名稱包括：
     - `orpo_alpha`
     - `orpo_lambda`
     - `lambda`
     - `beta`
   - 如果官方模板 `unsloth_orpo_template.py` 有明確寫法，請照官方模板。
   - 如果沒有明確寫法，請使用一個保守的 ORPO weight，例如 `0.05` 或 `0.1`。
   - 不要傳入 `ORPOConfig` 不支持的參數，否則會報錯。
   - 可以通過檢查函式簽名或 `dataclass fields` 的方式做兼容性處理。

7. 如果 `ORPOConfig` 支持：
   - `max_length = MAX_SEQ_LENGTH`
   - `max_prompt_length = 512`
   - `truncation_mode` 如果支持，請設置合理值。
   - 如果資料都很短，可以不啟用截斷，而是直接過濾過長樣本。

8. 不要在 ORPO 階段使用過多不同模板。
   - 模板必須固定。
   - 與 SFT 階段一致。

9. 如果訓練過程中出現 OOM：
   - 代碼中請註解說明可將：

     - `GRADIENT_ACCUMULATION_STEPS` 增加
